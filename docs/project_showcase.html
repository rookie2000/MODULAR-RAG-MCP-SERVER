System Architecture

从模块到面试故事的架构图

核心不是“有几个文件”，而是每层都有清晰职责：摄取负责数据质量，检索负责召回，MCP 负责对外能力，观测评估负责持续优化。

数据进入系统

通过 `IngestionPipeline` 统一编排加载、分块、增强、编码和入库，支持 SHA256 增量跳过。

  • PDF loader with image extraction
  • Chunk refinement and metadata enrichment
  • ChromaDB + BM25 index

查询被拆成能力链

查询先经过 dense/sparse 双路召回，再通过 RRF 融合和可选 rerank，最后构造成带引用的响应。

  • Dense semantic retrieval
  • BM25 sparse retrieval
  • Citation-aware response builder

能力通过 MCP 暴露

ProtocolHandler 统一注册工具，让 Copilot、Claude Desktop 等 MCP Client 可以直接调用知识库能力。

  • JSON Schema tool inputs
  • Async tool execution
  • Graceful error handling

End-to-End Flow

五步讲清完整 RAG 链路

点击每一步可以看到它在项目中的职责。面试时按这条线讲，能自然覆盖工程化、可观测和效果优化。

数据摄取

从 PDF 和图片开始，做完整性检查、解析、图片存储与原始文档结构化。

  • PdfLoader
  • SQLiteIntegrityChecker
分块增强

通过 splitter、chunk refiner、metadata enricher 和 image captioner 提升 chunk 可检索性。

  • DocumentChunker
  • Vision LLM captions
混合检索

Dense 向量召回负责语义，BM25 负责关键词，RRF 把两路结果融合。

  • HybridSearch
  • Dense + Sparse
重排生成

可选 Cross-Encoder 或 LLM rerank，随后 ResponseBuilder 生成带引用的工具响应。

  • CoreReranker
  • CitationGenerator
观测评估

Trace 记录中间状态，Dashboard 展示链路，Ragas/Custom Evaluator 做回归评估。

  • TraceCollector
  • EvalRunner

Provider Matrix

可插拔能力矩阵

项目用 factory/base-class 模式把服务商差异收束在 `src/libs/`，配置切换后端，主链路尽量不感知具体 provider。

LLM

文本生成与 chunk 增强能力，通过 LLMFactory 管理。

openaiazuredeepseekollamaminimax

Vision LLM

用于图片理解和 image captioning，让图片内容进入文本 RAG 链路。

azureopenai

Embedding

负责 dense vector 编码，接入多种 embedding provider。

openaiazureollamaminimax

MCP Tools

对外暴露的三类知识库工具

这些工具是项目和 Agent 生态之间的接口。它们让 RAG 不只是脚本，而是可被模型客户端直接调用的能力。

query_knowledge_hub

输入 query、top_k、collection，走混合检索与可选重排，返回带 source citation 的结果。适合讲“Agent 如何访问知识库”。

src/mcp_server/tools/query_knowledge_hub.py

list_collections

枚举当前知识库集合，让客户端知道有哪些文档空间可查询。适合讲多 collection 管理和数据边界。

src/mcp_server/tools/list_collections.py

get_document_summary

围绕指定文档生成摘要或结构化概览，适合在演示中展示“先理解文档，再问具体问题”的交互路径。

src/mcp_server/tools/get_document_summary.py

Observability & Evaluation

把 RAG 从黑盒变成可调系统

面试里最容易拉开差距的点，是能否解释“效果不好时怎么定位”。这个项目给了链路追踪、Dashboard 和评估回归三件工具。

Streamlit Dashboard

多页面管理入口，覆盖 Overview、Data Browser、Ingestion Manager、Trace 和 Evaluation Panel。

src/observability/dashboard/app.py

Trace System

TraceContext 和 TraceCollector 记录摄取/查询中间状态，支撑回放、排查和演示。

src/core/trace/trace_collector.py

Evaluation Runner

Custom/Ragas/Composite 评估体系用于 golden set 回归，帮助用指标驱动迭代。

src/observability/evaluation/eval_runner.py

Quick Start

Interview Pitch

面试时可以这样讲

这里把项目压缩成“能讲、能追问、能展示”的表达材料。

我做了一个模块化 RAG MCP Server，把文档摄取、混合检索、重排、MCP 工具暴露、可观测 Dashboard 和评估回归串成完整工程链路，核心特点是可插拔、可追踪、可被 Agent 客户端直接调用。

技术亮点

  • BM25 + Dense + RRF + Rerank
  • Vision captioning 复用文本 RAG
  • Factory pattern 管理 provider

可追问点

  • 为什么混合检索优于单向量召回
  • 如何处理图片和 PDF 中的非文本信息
  • 如何用 trace 定位召回质量问题

演示路径

  • 先启动 Dashboard 看数据和 trace
  • 再通过 MCP 工具查询知识库
  • 最后展示 evaluation 回归结果
